# 网页审批闭环

范围：让故障诊断中的人工审查在页面完成，并继续同一次任务。用户已授权前后端及审批策略修改。资源解析、CMDB、Neo4j、RAG 和命令风险规则不在本轮修改范围。

## 已确定的实现

- 审批默认使用 web 策略，保留 email 策略；审批渠道只改变请求如何交付，风险判断和执行授权不变。
- 审批记录包含会话、原始命令、目标主机、SSH 用户、风险、状态和执行结果，保存到现有可写 data 路径。
- ReAct 调用网页确认工具后立即返回；外层图保存检查点并暂停，不在 HTTP 请求里等待用户或邮箱。
- 前端展示不可编辑的实际操作，可批准或拒绝；请求携带同一 session_id、approval_id，禁止替换命令。
- 后端从同一检查点恢复，只有批准记录中的命令能够执行；拒绝不执行，重复请求不重复执行。
- SSH 用户补充与命令批准是两种不同审查，页面分别显示输入或批准/拒绝，不把用户名当作命令授权。
- 现有检查点是进程内存；重启后旧会话明确失效，持久化审批记录不自动重放命令。
- 网页决定要求已登录管理员；会话读取只允许发起者或管理员。

## 验证

先验证无 SMTP、批准、拒绝、错会话、重复请求、执行失败和重启失效。再在真实 Ubuntu 上提交一次只读命令审批，经页面批准后读取商城状态并继续诊断。保留原始记录和浏览器结果，不以接口 200 代替审批及执行成功。
